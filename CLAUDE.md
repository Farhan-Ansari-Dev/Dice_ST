# DICE Engineering Specification

This document is the permanent engineering specification for the DICE platform.

Every implementation must prioritize:

- Security
- Stability
- Scalability
- Maintainability
- Performance
- Production readiness

Never sacrifice stability for speed.

Every code change must preserve existing functionality.

Never modify business logic without explicit approval.

Never change public API contracts without explicit approval.

Never change authentication architecture without explicit approval.

Never change database schema without explicit approval.

Reuse existing components whenever possible.

Avoid duplicate code.

Perform validation before implementation.

Perform self-review after implementation.

No TODO code.

No placeholder implementations.

Only production-ready code.

# FILE MODIFICATION RULES

Before coding

List every file that will be modified.

If more than five files are required

STOP.

Ask for approval.

Never modify shared components unless absolutely necessary.
